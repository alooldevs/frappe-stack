# frappe-stack: native mode

Continues from [README](README.md) steps 1–5, with `host-prep.sh native`. The classic setup, without Docker:
each bench is a folder in `/srv/benches/`, run by supervisor behind the host's nginx, using the host's
MariaDB 11.8. HTTPS comes from certbot, which renews on its own. Driven by `bin/native`.

```
Internet :80/:443 → nginx ─┬→ /srv/benches/alpha: gunicorn :8000 · socketio :9000 · workers · redis :11000/:13000
                           └→ /srv/benches/beta:  gunicorn :8001 · socketio :9001 · workers · redis :11001/:13001
                  MariaDB 11.8 (localhost)
```
bench gives every bench in `/srv/benches` its own ports automatically. Keep all benches in that one folder.

**6. Database login and backups** (1 min)
```sh
native init you@example.org
```
This creates a MariaDB admin login for creating sites (Ubuntu's MariaDB root only logs in by socket) and
saves it in `~/stack/env/native.env`. It also schedules the nightly backup.

**7. First bench** (≈5 min for Frappe, plus a few minutes per app)
```sh
native new-bench alpha                                              # upstream Frappe version-16
# native new-bench alpha git@github-ACCOUNT:OWNER/frappe.git BRANCH # or your fork, through a step 4 alias
native bench alpha get-app git@github-ACCOUNT:OWNER/app_one.git --branch develop
native bench alpha get-app git@github-ACCOUNT:OWNER/app_two.git --branch develop
```
`new-bench` runs `bench init` with Python 3.14, turns on DNS multitenancy, and wires the bench into
supervisor and nginx. Two warnings in its output are harmless: `supervisorctl restart frappe: … no such
group` (bench tries a restart before the bench has supervisor groups) and `Cannot connect to redis_cache
to update assets_json` (the first build runs before the bench's Redis exists).

**8. First site** (≈3 min)
```sh
native site alpha erp.example.org app_one app_two
```
This creates the site and installs the apps, turns on the scheduler, sets `host_name`, gets a Let's Encrypt
certificate, regenerates nginx for HTTPS, and waits until the site answers. Then it prints where the
Administrator password is (`~/stack/env/alpha.passwords`).
Log in and finish the setup wizard. Set the **time zone** there, because a new site starts on Asia/Kolkata.

## Day to day

| Task | Command |
|---|---|
| What's running | `native ps` |
| Any bench command | `native bench alpha --site erp.example.org migrate` |
| Add an app | `native bench alpha get-app <url> --branch <b>` then `native bench alpha --site <site> install-app <app>` |
| Update code (pull, patch, build) | `native bench alpha update` |
| Restart a bench | `native restart alpha` |
| Add a site | point DNS, then `native site alpha new.example.org app_one` |
| Add a bench | `native new-bench beta [frappe-url] [branch]` → `get-app` … → `native site beta x.example.org …` |
| After changing domains or ports | `native apply alpha` (regenerates nginx + supervisor, reloads) |
| Backup now | `native backup` (nightly at 02:00 UTC; log in `~/stack/logs/backup.log`) |

A bench with a different Python: `NATIVE_PYTHON=3.12 native new-bench old …` (install it first with
`uv python install 3.12`).

## Why it's done this way

- **No `bench setup production`.** On Ubuntu 24.04 it tries to pip-install ansible into bench's own env
  and fails. On a first run it also skips the supervisor link. `native apply` does the same steps directly:
  `bench setup supervisor` + `bench setup nginx --logging none`, links both into `/etc`, then reloads.
- **No `bench setup lets-encrypt`.** It stops nginx to get a certificate, which takes every bench offline.
  `certbot certonly --nginx` doesn't; its systemd timer renews and reloads nginx.
- **Node from NodeSource, not nvm.** Supervisor and sudo can't see an nvm-installed node.
- **`/srv/benches`, not `/home`.** Ubuntu 24.04 home folders are `0750`, so nginx couldn't read the assets.
- **A catch-all server** (`/etc/nginx/conf.d/00-stack.conf`) drops requests for unknown hosts instead of
  showing the first bench's site.
- **One Redis per bench,** started by supervisor from bench's own config. The system `redis-server`
  service is off.

## Files

| Path | What |
|---|---|
| `/srv/benches/<bench>/` | the bench: apps, sites, logs, `config/` (generated nginx + supervisor) |
| `/etc/nginx/conf.d/<bench>.conf`, `/etc/supervisor/conf.d/<bench>.conf` | links to that bench's `config/` |
| `/etc/nginx/conf.d/00-stack.conf` | catch-all for unknown hosts, `server_names_hash_bucket_size` |
| `/etc/mysql/mariadb.conf.d/99-frappe.cnf` | utf8mb4 settings, buffer pool |
| `/etc/letsencrypt/live/<site>/` | certificates (certbot renews them twice a day if due) |
| `~/stack/env/native.env` | Let's Encrypt email, MariaDB admin login (mode 600) |
| `~/stack/env/<bench>.passwords` | Administrator passwords generated by `native site` |

## Good to know

- **Backups stay on this disk.** They protect against app mistakes, not against losing the VM. Copy them
  off-site yourself.
- **Test a renewal** with `sudo certbot renew --dry-run --no-random-sleep-on-renew`. Without the flag,
  certbot first waits a random 0–8 minutes.
- **Bench names must be unique on the host.** They name the supervisor programs and nginx upstreams.
- **PDFs:** wkhtmltopdf 0.12.6.1 with patched Qt is installed (Frappe v16's default). For Chrome-based
  print formats, run `native bench alpha setup-chrome`.
